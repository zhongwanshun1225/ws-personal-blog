# 全盘扫描：功能缺口与技术闭环

> 扫描时间：2026-10-13
> 对象：WS Personal Blog（Python 静态生成器 + CloudBase 账号/互动/云端发文）
> 方法：通读构建内核、页面模板、6 个前端脚本、云端 6 表 8 函数与 RLS、CI 工作流

---

## 0. 一句话结论

站点在「**静态发布**」这条主链上已经完整闭环（写 → 构建 → 部署 → 搜索 → RSS），
但在「**动态交流**」这条链上存在 **3 个硬断点**：

1. **两套内容体系互不相通** —— 云端发的文章搜不到、订阅不到、不进标签与 sitemap
2. **发文配不了图** —— 后台编辑器无法上传图片，云存储能力完全闲置
3. **评论是死胡同** —— 不能回复、没有通知、没有浏览量，发出去没人知道

其余为体验与工程化缺口，按优先级列在最后。

## 2. 技术闭环断点（P0 —— 建议优先补）

### 2.1 两套内容体系割裂 🔴 最大缺口

**现象**：静态文章（`content/posts/*.md`）与云端文章（`cloud_posts` 表）是两条完全独立的链路，互不感知。

| 能力 | 静态文章 | 云端文章 |
| --- | --- | --- |
| 出现在首页/统计 | ✅ | ❌ |
| 进入客户端搜索索引 | ✅ | ❌ |
| 进入 `sitemap.xml` | ✅ | ❌ |
| 进入 RSS `feed.xml` | ✅ | ❌ |
| 归入标签体系 | ✅ | ❌ |
| 详情页有 TOC | ✅ | ❌ |
| 有阅读进度/代码复制/图片放大 | ✅ | 部分（客户端渲染未接这些增强） |
| 上一篇 / 下一篇 | ✅ | ❌ |

**为什么是断点**：读者用搜索找不到你后台上发的文章；订阅者收不到更新；
搜索引擎不会收录（SEO 归零）。等于「后台发文」只对已进入 `posts.html` 列表的人可见。

**可选解法（按投入排序）**
- **A. 构建期拉取（推荐）**：`build.py` 构建时用 publishableKey 读取 `cloud_posts` 已发布文章，
  合并进搜索索引 / sitemap / RSS / 首页统计。改动集中在 `build.py`，前端不动。
- **B. 发布时触发重建**：后台「发布」后调用 GitHub `repository_dispatch` 触发一次 Actions 重建，
  把云文章落成静态页。
- **C. 反向统一**：干脆让云文章只做「随手记」，正式文章一律走 Markdown + git（成本最低，但放弃在线发文）。

### 2.2 后台发文无法配图 🔴

**现象**：`admin.js` 编辑器只有一个 Markdown `textarea`，没有插入/上传图片的能力；
`cloud.config.json` 里也没有接 CloudBase 存储。个人中心头像同样只能**填 URL**，不能上传。

**为什么是断点**：技术文章几乎必然要贴架构图、报错截图、代码对比图。
现在只能先传图到别处再外链，否则发不了——「在线发文」这条链在最常用的环节断掉。

**解法**：接入 CloudBase 文件存储（`storage`），编辑器加「上传图片」按钮 →
上传得 URL → 插入 Markdown `![]()`；顺手把头像也改成上传。

### 2.3 评论是死胡同 🔴

**现象**：评论能发、能删，但：

- **不能回复**：`comments` 表无 `parent_id`，无法针对某条评论回复（无楼中楼）
- **没有通知**：有人评论/回复，站长和作者都收不到任何提醒（无邮件、无站内信）
- **没有浏览量**：文章无 PV 统计，不知道哪些内容真有人看
- **默认直接公开**：`status` 默认 `'visible'`，没有「待审核」前置流程，无敏感词/频率限制/防刷

**为什么是断点**：「交流博客」的核心是交流闭环——
**读者评论 → 作者知道 → 作者回复 → 读者收到 → 再互动**。
现在链在第 2 环就断了（作者不知道），评论区沦为一次性留言板。

**解法（最小可用）**
1. `comments` 加 `parent_id`（自引用外键），前端加「回复」按钮
2. 站长通知：评论插入时用 CloudBase 邮件能力 / 或 webhook 通知到你的邮箱
3. 加 `views` 计数（云文章可在一个 `post_views` 表或直接在读取函数里 +1）
4. 评论默认 `status = 'pending'`，后台一键通过；后台已有「显示中/已隐藏」筛选，扩成三态即可

## 9. 建议路线图

**第一优先级 · 补断点（让动态链跑通）**
1. 云文章合并进搜索 / sitemap / RSS / 首页（方案 2.1-A）
2. 接入 CloudBase 存储，编辑器支持图片上传（2.2）
3. 评论：`parent_id` 回复 + 站长通知 + PV 计数 + 待审核（2.3）

**第二优先级 · 内容生产力（P1）**
4. 定时发布、草稿预览链接、封面图
5. 列表页展示互动数、热门排序、用户公开主页

**第三优先级 · 体验与工程（P2）**
6. 明暗主题切换 + 移动端目录
7. 找回密码 / 邮箱验证
8. CI 加 lint + 测试、接入访问统计与错误上报

## 附：不在建议范围内（个人博客可不做）

- 全文检索服务端化（Elasticsearch/Meilisearch）—— 内容量小时客户端索引足够
- 复杂权限体系（多角色/团队协作）—— 个人博客双身份已够用
- 评论表情包/富文本编辑器 —— 技术博客纯文本 + 代码块即可
