## 0. 身份模型：本站在传统网站谱系里的位置

传统内容站点（WordPress / Ghost / Medium / 掘金 / CSDN / 知乎专栏 / 传统论坛）通常划分 5~7 类身份。
本站实现了其中 4 类，其中 1 类残缺：

| # | 传统网站身份 | 本站 | 落地形态 | 缺口密度 |
| --- | --- | --- | --- | --- |
| 1 | 游客 Visitor | ✅ 已实现 | 无需登录浏览全部公开内容 | 中 |
| 2 | 注册读者 Member | ✅ 已实现 | 评论 / 点赞 / 收藏 / 个人中心 | **高** |
| 3 | 投稿作者 Contributor·Author | ✅ 已实现 | `/write.html` 写稿 → 送审 → 发布 | 中 |
| 4 | 编辑 Editor（二审角色） | ❌ **缺失** | 无中间层，只有「管理员」一档 | — |
| 5 | 管理员 Administrator | ✅ 已实现 | `/admin.html` 六面板 | 中 |
| 6 | 付费订阅者 Subscriber | ⛔ 不适用 | 个人博客形态，建议不做 | — |
| 7 | 机器身份（爬虫 / RSS / 社交抓取） | ⚠️ 部分 | RSS·sitemap 完备，社交分享图缺失 | 中 |
| 8 | 受限账号（禁言 / 封禁 / 注销中） | ⚠️ 部分 | 可禁用并拦截写操作，但无原因/期限/申诉 | 低 |

> **一句话结论**：`浏览 → 注册 → 互动 → 投稿 → 审核 → 发布 → 管理` 这条**主链已闭环**；
> 缺的是 **通知（人找得到你）**、**社区（人与人之间）**、**运营（数据与在线配置）**、**合规（隐私与注销）** 四类横向能力。

## 1. 游客（未登录）

### 1.1 已有的能力

- 首页（Hero / 实时统计 / 文章列表 / 标签筛选 / 精选项目）、文章列表、文章详情、项目集与详情、归档（按年）、标签云与标签详情、关于、404
- 站内搜索：客户端索引，`Ctrl / ⌘ + K` 与 `/` 唤起，键盘上下选择，**单次最多 12 条**
- 阅读增强：目录（桌面悬浮 + 移动端可展开卡片）、滚动高亮、阅读进度条、代码高亮与一键复制、图片点击放大、上一篇 / 下一篇、**静态文章**的相关推荐
- 外观：跟随系统 / 浅色 / 深色 + 5 种强调色，首屏防闪；`prefers-reduced-motion` 已适配
- 面包屑：文章详情、项目详情、标签详情**已有**（其余页面没有）
- 分发：`feed.xml`、`sitemap.xml`、`robots.txt`、canonical、og:type/title/description/url、twitter:card、静态文章 JSON-LD `BlogPosting`
- 互动区可见：点赞数 / 收藏 / 评论 / 阅读量都展示，点下去才要求登录

### 1.2 缺失的功能

| # | 缺口 | 传统网站对照 | 影响 | 落点 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| V1 | **无公开用户主页** | WP `/author/nickname`、掘金 `/user/xxx`、知乎 `/people/xxx` | 文章页能看到作者昵称，点不动；读者无法认识「这个人还写过什么」 | 新增 `author.html?u=uid`（走 `profiles_public`） | **P0** |
| V2 | **无「热门 / 最热」排序** | CSDN「排行榜」、掘金「热门」 | 只有时间倒序，优质老文永远沉底；已有 `post_views` 数据却只用来显示数字 | 列表页加排序切换 + 按 views 排序的 RPC | P1 |
| V3 | **列表无分页 / 加载更多** | 所有传统站点标配 | `site.config.json` 里 `postsPerPage` 定义了但**代码从未读取**；文章一多首页会无限长、首屏变慢 | `build.py` 列表渲染 + `pages.py` 分页组件，或前端「加载更多」 | P1 |
| V4 | **搜索不可分享 / 不可后退** | 站点普遍支持 `?q=` 或 `/search?q=` | 搜完发给别人的链接是首页；刷新丢结果；浏览器后退行为错乱 | `app.js` 读写 `location.search`，加 history 同步 | P1 |
| V5 | **无分享按钮** | 国内站点标配「分享到微博 / 复制链接」 | 想转发只能手动复制地址栏 | 文章头加分享组（复制链接 / 微博 / X / 系统 share API） | P1 |
| V6 | **无「最新评论 / 站点动态」** | WP 侧边栏「近期评论」、论坛「最新回复」 | 访客看不到站点是否还活着，评论区永远是黑的 | 首页或文章列表页加轻量区块（`post_comments` 已有数据） | P2 |
| V7 | **只有扁平标签，没有分类 / 系列** | WP Category + Tag 双层；掘金「专栏」 | 连载教程、专题无法归组；标签一多就失焦（现有 14 个） | `cloud_posts` / front-matter 加 `series` + 系列聚合页 | P2 |
| V8 | **og:image 缺失但已声明 `summary_large_image`** | 所有站点标配分享卡 | 分享到微信 / X / 飞书是**白板卡片**，点击率腰斩 | 文章模型加 `cover` 字段 + `layout.py` 输出 `og:image` | P1 |
| V9 | **404 页无补救路径** | 传统 404 给搜索框 + 热门文章 | 只能「返回首页」，访客直接流失 | `pages.py::not_found_page` 加搜索触发 + 热门 5 篇 | P2 |
| V10 | **面包屑覆盖不全** | 传统站点全站可见 | 首页 / 文章列表 / 归档 / 标签云无面包屑，层级感不一致 | `layout.py` 统一由 config 推导或各页补齐 | P2 |
| V11 | **无邮件订阅（RSS 之外）** | Medium / Ghost / 独立博客普遍有 | 非技术读者不用 RSS，等于没有订阅渠道 | 需邮件服务（或 CloudBase 邮件能力）+ 订阅表 | P2 |
| V12 | **无数学公式 / 图表渲染** | 技术博客常见 KaTeX + Mermaid | 算法、架构类文章只能用截图代替，无法复制 | `markdown.py` 加 KaTeX / mermaid 分支 + 本地 vendor 包 | P2 |
| V13 | **无 i18n** | 多语言站点有语言切换 | 只有 `zh-CN`；对外分享受限 | 工作量大，个人博客可缓 | P2 |
| V14 | **无 PWA / 离线** | 现代站点有 manifest + SW | 无法「添加到主屏」、离线读不了 | `manifest.webmanifest` + `sw.js` | P2 |

## 2. 注册读者（Member）

### 2.1 已有的能力

- 登录：邮箱 + 密码、邮箱验证码（首次验证码登录自动注册并设密码）；**忘记密码**自助重置（验证码 → 设新密码 → 自动登录）
- 管理员登录后多一步「选择身份」（普通用户 / 进入后台），可随时切换
- 个人中心：昵称、头像（**支持上传**，也可填 URL）、个人简介
- 我的评论 / 我的点赞 / 我的收藏 / **我的投稿**（状态徽章 + 驳回理由 + 编辑入口）
- 互动：点赞、收藏、评论（两级楼中楼、可回复、可删自己的评论）、阅读量展示
- 被禁用账号：仍可浏览，写入被数据库策略拦截，前端同步拦截并提示

### 2.2 缺失的功能

| # | 缺口 | 传统网站对照 | 影响 | 优先级 |
| --- | --- | --- | --- | --- |
| M1 | **无站内通知中心** | 掘金「消息」、知乎「通知」、WP 后台通知 | 有人回复我 / 我的投稿被通过或驳回，**除了自己回去翻投稿页，完全不知道**。互动闭环在第 2 环断掉 | **P0** |
| M2 | **无评论编辑** | 多数站点允许限时编辑 | 打错字只能删了重发，楼层结构错乱 | P1 |

| M4 | **无 @ 提及** | 论坛 / 掘金 | 无法定向提醒别人 | P2 |
| M5 | **个人中心无「安全设置」** | 传统站点「账号安全」独立页 | 已登录状态下**不能改密码**（只能走忘记密码绕一圈）；不能改邮箱 | **P0** |

| M9 | **无邮箱验证状态与验证入口** | 传统站点注册即发验证邮件 | 只有「验证码登录」这条路径间接证明邮箱归属；密码注册路径下邮箱未验证 | P1 |

| M15 | **无「完善资料」新手引导** | 传统站点首次登录有引导 | 新用户默认昵称为邮箱前缀，评论区显示体验差 | P2 |

## 3. 投稿作者（Contributor）

### 3.1 已有的能力

- `/write.html`：Markdown 编辑器、**实时预览**、**插图上传**（云存储 → 自动插入 `![]()`）、标签 / 摘要 / 自定义 slug
- 状态机：`draft`（草稿，仅自己可见）→ `pending`（提交审核，可撤回）→ `published`（通过，前台可见）
  / `rejected`（驳回，显示站长理由，改完可重投）
- 已发布文章作者端**只读**（需站长下架后才能改）；管理员自己写的不走审核
- 权限边界在数据库：RLS 限定投稿者只能写 `draft / pending / rejected`

### 3.2 缺失的功能

| # | 缺口 | 传统网站对照 | 影响 | 优先级 |
| --- | --- | --- | --- | --- |
| A1 | **无草稿自动保存** | WP 每 60 秒自动保存、掘金实时存 | 切页 / 崩溃 / 手滑刷新 = **稿件全丢**，只有手动点保存才落库。这是编辑器最痛的缺口 | **P0** |
| A2 | **无本地草稿恢复** | 几乎所有在线编辑器 | 断网、会话过期时写的内容直接蒸发 | **P0** |
| A3 | **无定时发布** | WP「发布：立即 / 定时」 | `published_at` 字段已存在，但只能立即发布，想卡点发不行 | P1 |
| A4 | **无草稿预览分享链接** | Ghost 有 preview link、WP 有「公开预览」 | 无法让朋友在发布前先看效果 | P1 |
| A5 | **无修订历史 / 回滚** | WP Revisions、掘金历史版本 | 改坏了无法还原，只能凭记忆重写 | P1 |
| A6 | **无封面图上传** | 所有现代 CMS | 列表卡片无缩略图、分享无图（与 V8 同源） | P1 |
| A7 | **无目录 / 大纲侧栏** | 掘金、语雀编辑器左侧大纲 | 长文编辑时来回滚动找段落 | P2 |
| A8 | **无字数 / 预计阅读时间实时提示** | 所有编辑器状态栏 | 后台列表有字数，编辑器里却看不到 | P2 |
| A9 | **无快捷键 / 工具栏** | `Ctrl+B`、插入链接/代码块按钮 | 全手写 Markdown，效率低 | P2 |
| A10 | **无图片管理（媒体库）** | WP 媒体库 | 上传过的图无法复用、无法删除，云存储只增不减 | P2 |
| A11 | **无片段 / 模板** | 常用提示块、代码壳模板 | 每次手打 `> [!TIP]` | P2 |
| A12 | **已发布文章不能申请修改** | WP 作者可改再送审 | 只能求站长下架 → 下架期间文章不可见，体验割裂 | P1 |
| A13 | **看不到自己文章的阅读量 / 评论** | 掘金创作者中心 | 作者缺少反馈，投稿动力衰减 | P1 |
| A14 | **无自定义 SEO 字段** | WP 的 SEO 插件 | 不能自定义 description / og:image / canonical | P2 |

### 4.2 缺失的功能

| # | 缺口 | 传统网站对照 | 影响 | 优先级 |
| --- | --- | --- | --- | --- |
| B1 | **所有后台列表都是全量拉取，无分页 / 搜索** | WP 后台全部列表都分页 + 可搜索 | `admin_posts()` 一次返回全部文章、评论列表硬编码 `limit(300)`、用户全量。**文章过百就会明显卡**，且找不到具体某篇 | **P0** |
| B2 | **无批量操作** | WP 列表页「全选 → 批量删除 / 移动」 | 清理垃圾评论要一条条点 | P1 |
| B3 | **没有通知渠道** | WP 新评论发邮件、新投稿发邮件 | 有人评论 / 投稿，**站长完全不知道**，只能自己定期去后台翻。这是运营侧最大的断点 | **P0** |
| B4 | **评论无「待审核」前置** | WP 首评必须审核 + 敏感词库 | 数据库 `comments.status` 的 CHECK **已允许 `pending`**，但默认直接 `visible`，UI 也只有全部/可见/已隐藏三档。无敏感词、无频率限制、无 IP/UA 记录 | **P0** |
| B5 | **无数据导出 / 备份** | WP 一键导出 XML / 数据库备份插件 | 文章、评论、用户无导出；云端数据无定期备份。**数据只在一处** | **P0** |
| B6 | **站点配置无法在线改** | WP「设置」面板 | 站点名、导航、社交、页脚、SEO 默认值、关于页技能/经历**全在 `site.config.json`**，改一次要提交代码 + 等 CI + 重新部署 | P1 |
| B7 | **无媒体库** | WP 媒体库 | 云存储 `runtime` bucket 里的文件无管理界面，无法删除无用图 | P1 |
| B8 | **内容管理缺置顶 / 排序权重 / 定时发布** | WP「置顶」「定时」 | 重要文章无法置顶（静态文章 front-matter 有 `pinned`，云文章没有） | P1 |
| B9 | **无统计图表 / 趋势** | WP 统计插件、Umami | 只有静态数字卡片，没有 7 日 / 30 日趋势、没有 Top 10 热门文章、没有评论趋势 | P1 |
| B10 | **无访问分析（PV / UV / 来源 / UA）** | Umami / Plausible / 百度统计 | 不知道流量从哪来、什么内容有人看（阅读量只有总数） | P1 |
| B11 | **权限只有「管理员」一档** | WP 有 订阅者 / 投稿者 / 作者 / 编辑 / 管理员 五档 | 无法委任「只能审评论」的帮手；第 0 节的「编辑 Editor」身份完全缺失 | P2 |
| B12 | **审计日志无筛选 / 分页 / 导出** | 传统后台日志可按操作者、时间、动作筛 | 刚落地，只有最近 100 条列表 | P2 |
| B13 | **无 2FA / 密码策略** | 传统后台支持两步验证 | 管理员账号被撞库 = 全站失守 | P1 |
| B14 | **无健康检查面板** | 运维面板 | 云服务连通性、最近构建时间、RSS / sitemap 生成时间都看不到 | P2 |
| B15 | **无站内公告 / 维护模式** | WP 维护模式插件 | 想临时挂「维护中」要改代码 | P2 |
| B16 | **无邮件模板管理** | WP 邮件模板插件 | 验证码邮件、驳回通知的文案无法调整 | P2 |
| B17 | **无审核规则自动化** | WP 敏感词库、Akismet 反垃圾 | 全人工，垃圾评论只能靠删除 | P1 |

## 5. 机器身份（搜索引擎 / RSS / 社交平台）

| # | 缺口 | 影响 | 优先级 |
