>
> **B3 站外通知渠道**（第七批补丁 C `2026-10-15-batch7c-notify-worker.sql` + 云函数 `ws-notify`）——
> 队列 / 设置 / 模板 / 重试 / 后台面板原本就绪，本轮把**最后一段管道**补上了：
> 云函数每 5 分钟定时领取 `notify_outbox`，经 **Webhook（HMAC-SHA256 签名）或 SMTP** 投递，
> 回执写回 `sent_at` / `last_error`，并把运行痕迹写进 `notify.worker_state` 供后台显示。
> 已实测端到端跑通一次（造一条队列记录 → 投递 → `sent=1 failed=0` → 回执落库）。
> **⚠️ 要真正开始投递还差两步配置（属配置项，不是缺口）**：
> ① 后台「通知」面板打开总开关，并填 Webhook 地址或开通邮件通道；
> ② 邮件通道需要在云函数 `ws-notify` 上补 `SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASS / MAIL_FROM / MAIL_TO` 环境变量。
> 另注意：在后台轮换投递密钥后，必须把新值同步到函数的 `NOTIFY_WORKER_SECRET`，否则 worker 会判 `SECRET_REJECTED` 静默停投
> （后台「投递队列」旁的 worker 状态会显示「还没有运行记录」，是它的可见信号）。

## 附 1. 复核方法（下次重扫怎么做）

- **代码侧**：`build.py`（产物与排序 + 云端合流）→ `wsblog/`（模板与管线，
  含 `cloudposts.py` / `cloudsettings.py`）→ `src/scripts/`（20 个前端脚本）→
  `.github/workflows/deploy.yml`（CI 步骤）→ `content/` 与 `site.config.json`。
- **云端侧**：`cloud/sql/` 下 12 个迁移归档文件是最好的入口，但要记住**线上才是事实**。
  云函数 `ws-notify`（站外投递 worker）不在 SQL 里，源码在 `cloudfunctions/ws-notify/`，
  它的部署状态要用 CloudBase 的函数查询接口核对，不要只看仓库。
  实测对象数量：
  ```sql
  SELECT (SELECT count(*) FROM information_schema.tables
           WHERE table_schema='public' AND table_type='BASE TABLE') AS tbls,
         (SELECT count(*) FROM information_schema.views
           WHERE table_schema='public') AS views,
         (SELECT count(*) FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
           WHERE n.nspname='public') AS funcs;
  ```
  （2026-10-15 实测：**25 表 + 4 视图 + 155 函数** = 145 个可直接调用 + 10 个触发器函数；
  触发器函数按 `prorettype='trigger'::regtype` 排除。新增迁移后需重查。）
  第七批新增的 8 张表：`site_settings` / `post_revisions` / `post_previews` / `notify_outbox` /
  `media_assets` / `user_totp` / `backup_snapshots` / `page_views_log`。
- **勾销纪律**：**提交说明不等于改动范围**。第三批的提交说明只写了「通知 / 草稿 / 分页」，
  实际同一提交里还落地了多项；反过来也见过「声称已做、其实没做」。
  所以勾销一条缺口必须以代码为准，可以用 `git log -S"<关键标识符>"` 反查落地批次。
- **「建好了」不等于「跑起来了」**：B3 的 worker 是定时云函数，SQL 建完函数、前端接好面板之后，
  还得确认它真的部署了、密钥真的对得上。复核时看三处：
  `select value from site_settings where key='notify.worker_state'`（心跳，超过 15 分钟没更新就是停了）、

## 附 2. 本地验不到的部分

⚠️ 另一个容易误判的点：**`admin.html` / `write.html` 在本地做 DOM 快照拿到的是登录页** ——
