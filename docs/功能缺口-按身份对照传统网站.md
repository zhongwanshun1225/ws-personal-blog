> 方法：**直接通读代码取证** —— 构建内核（`build.py` + `wsblog/`）、页面模板、14 个前端脚本、

## 读法

- **编号沿用首版**（`V / M / A / B / R / S / E / L / C` 前缀），**已闭环的编号不再出现** ——
  这样历史记录与其他文档里的编号仍能对上，不会因为删条目而错位。
- **P0**：不补就有实质损失（合规 / 数据 / 安全 / 主链断点）；**P1**：明显影响使用或运营；**P2**：体验优化。
- 标「部分实现」的条目只描述**未做的那半**，已做的那半用一句话交代前提。
- 身份前提：本站已实现 **游客 / 注册读者 / 投稿作者 / 管理员 / 机器身份** 五类身份；
  **唯一缺失的身份是「编辑 Editor」（二审角色）**，归入 B11；「付费订阅者」不适用于个人博客形态。

## 9. 建议实施顺序（只列尚未做的）

### 第一梯队 · 断点与合规（做完才算真正可运营）

1. **隐私政策 + 用户协议页**（L1 / L2，纯静态内容，成本最低、合规收益最大）
2. **数据导出与备份**（B5，先做一个「一键导出 JSON」+ 每日快照）
3. **账号注销与数据导出**（M7，需要先解 S3：确认云平台是否支持删除登录账号）
4. **站外通知渠道**（B3，先做「新评论 / 新投稿 → 邮件通知站长」）
5. **测试进 CI + 前端错误上报**（E1 / E2）

## 附 1. 复核方法（下次重扫怎么做）

- **代码侧**：`build.py`（产物与排序）→ `wsblog/`（模板与管线）→ `src/scripts/`（14 个前端脚本）→
  `.github/workflows/deploy.yml`（CI 步骤）→ `content/` 与 `site.config.json`。
- **云端侧**：`cloud/sql/` 下 7 个迁移归档文件是最好的入口，但要记住**线上才是事实**。
  实测对象数量：
  ```sql
  SELECT (SELECT count(*) FROM information_schema.tables
           WHERE table_schema='public' AND table_type='BASE TABLE') AS tbls,
         (SELECT count(*) FROM information_schema.views
           WHERE table_schema='public') AS views,
         (SELECT count(*) FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
           WHERE n.nspname='public') AS funcs;
  ```
  （当前为 11 表 + 2 视图 + 42 函数 = 35 个可直接调用 + 7 个触发器函数；
  触发器函数按 `prorettype='trigger'::regtype` 排除。新增迁移后需重查。）
- **勾销纪律**：**提交说明不等于改动范围**。第三批的提交说明只写了「通知 / 草稿 / 分页」，
  实际同一提交里还落地了多项；反过来也见过「声称已做、其实没做」。
  所以勾销一条缺口必须以代码为准，可以用 `git log -S"<关键标识符>"` 反查落地批次。
